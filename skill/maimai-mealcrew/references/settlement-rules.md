# 分摊与补贴规则

金额一律为非负整数分，数量为正整数；不接受字符串数字、布尔值或小数。成员与商品 ID 唯一，共享成员不重复且属于当前会话。

## 优惠与对账

- 商品净额 = 单价 × 数量 − 商品级优惠；商品优惠不得超过该商品金额。
- 订单级优惠适用于明确的 `ALL` 或非空有效商品 ID 列表，不得超过适用商品净额；范围失效要求重新核价，不能扩大到全单。
- 订单优惠按适用商品净额用最大余数法分配，尾差按输入顺序确定。
- 所有模式均检查：商品净额合计 − 订单优惠 + 公共费用 = 官方最终应付。
- 官方只给总价且无法形成可信明细时，保留诊断，不输出正式账单；当前版本不提供任意总额直接分账的绕过入口。

## 个人与共享餐

`itemized` 按个人商品归属计费；共享餐及优惠在明确的共享成员中均分。公共费用按 `equal` 或餐费比例 `by_meal_cost` 分摊；餐费全零时费用均分。

`equal_split` 忽略商品的个人归属，全单含费用应付均分。先均分餐费，再将均分总额与餐费的差记作费用，确保每人的补贴前金额相差最多一分，餐费和费用合计各自守恒。

## 公司补贴

- `per_person` 为每人额度，`whole_order` 为全单额度；仅向 `eligible` 指定成员分配。
- `covers_public_fees=true`：基数为该成员餐费加公共费用；false：基数仅为餐费。两种结算模式均适用。
- 公司承担不超过可补贴基数，未用额度不转成个人收入；个人自付不为负。
- 全单额度按可补贴基数比例分配，不超过各成员基数。

## 结算与确认

正式输出前调用 `require_valid_settlement`。任何对账或守恒失败均返回非零，不写新账单；已存在的输出文件也不覆盖。渲染入口同样执行检查。

改商品、门店、渠道、优惠输入或费用需要重核报价；只改补贴或商品承担人可以复用同一核价输入对应的报价，但新账单仍需确认。每次改单清除旧确认；逐人金额、补贴、分摊方式、优惠归属或公共费用变化都要求重新确认。

演示改单仅重算输入的合成金额，不模拟真实券资格或满减门槛。若演示优惠因删餐超过适用净额，明确阻断并要求更新演示输入。
